# RM-001-P1 — Capability and consumer compatibility matrix

**Evidence class:** source inspection at Aria Ephemeris `36a9cec` (v0.1.0; prompt documentation merged), Aria Galaxy `4ab5f99` on 18 November 2026. **Not** a live comparison or an accepted provider substitution. See [calculation contract](p1-calculation-contract.md), [launch decisions](p1-launch-scope-and-decisions.md), [qualification baseline](p1-qualification-baseline.md) and [RM-001/001](prompts/001-commercial-calculation-contract-and-baseline.md).

## Reading this inventory

Every row uses these required columns. **Implemented** = Aria Ephemeris v0.1.0 source capability, not app integration; **Qualification** = *historical* tests/measurement only. **MVP** = proposed scope requiring owner approval, never a claim the commercial application supports this feature through Aria. "E" refers to the engine repository and "A" to the read-only application repository; linked source definitions are at the foot of this page. `P2/P3/P4/P5/P7/P8` = follow-up phases in RM-001. **Owner** is a proposed accountable role, not an assignment.

Current application boundary: `/api/v1/ephemeris/latitudes[/range]` → [A-RANGE] → [A-ADAPT]/[A-ACT] for activation, while `/api/v1/horoscope/chart` → [A-CHART] → [A-WHEEL]/[A-DATA] for charts. These are **two independent sweph consumers**: changing the series adapter does not migrate chart calculations. [A-ARCH] also documents a separate PostgreSQL historical-event catalogue; do not confuse that with Aria's astronomical event root searches.

## Evidence/decision boundaries

- **Source inspection** establishes that an implementation branch exists, not that any live service correctly computes the case. No source comparison can establish absolute planetary centre parity or sidereal accuracy. For all F01–F11 fixtures see [qualification baseline](p1-qualification-baseline.md).
- **Object/calc availability** must be returned per requested point and may depend on data/epoch; absence must be `unavailable` with reason or an explicit structured request failure. The current application's fallback/compatibility is not permission to reproduce it uncritically.
- **All MVP proposals remain Open**, particularly the six barycentre/centre choices and scope of dates, houses, sidereal and nodes. The owner must approve a consistent scope before P2/P3/P4 can be promoted to Ready.
