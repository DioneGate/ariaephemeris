## Objective and expected behaviour

Deliver a **frozen external astronomical benchmark** for six planetary physical centres (Mars 499, Jupiter 599, Saturn 699, Uranus 799, Neptune 899, Pluto 999), independently generated by NASA/JPL Horizons rather than derived from Aria's source or output. The dataset must be reproducible, identify model differences, and support WP5.2's future numerical comparator without requiring network access during tests.

The external reference must not be silently described as using the same dynamical model as Aria (DE442s plus pinned supplementary centre offsets). Independent results may differ for scientifically legitimate source-model reasons.

## Verified baseline

- `planet-centres-v1` profile exists on main after WP4 PR #6; it calculates each centre from DE442s planetary barycentre and separately hash-pinned original satellite offsets. The legacy `reference` profile remains unchanged.
- WP3's same-source CSPICE comparisons verify the data evaluator, **not** independent apparent chart or source-model accuracy.
- [Horizons API v1.3 documentation](https://ssd-api.jpl.nasa.gov/doc/horizons.html) defines `TIME_TYPE=TDB` vector dates and `TIME_TYPE=TT` observer dates, `TLIST_TYPE=JD`, ICRF and output control parameters.
- [Horizons manual](https://ssd.jpl.nasa.gov/horizons/manual.html) defines observable **quantity 45** as inertial-frame apparent RA/Dec (down-leg light-time, gravitational deflection and stellar aberration).
- [NASA/JPL public API fair-use policy](https://ssd-api.jpl.nasa.gov/doc/) requests *serial*, non-redundant traffic, sensible backoff and identifiable user agent.

## Included scope

1. Query **each of six physical-centre IDs** separately for 25 independently specified epochs each, preserving the operational 1900–2100 period, internal centre-source joins (±0.04 day), J2000 and selected modern dates.
2. Acquire **two independent reference types** for each target against Earth's geocentre (399):
   - **Geometric**: `EPHEM_TYPE=VECTORS, CENTER='500@399', REF_PLANE=FRAME, REF_SYSTEM=ICRF, VEC_CORR=NONE, VEC_TABLE=2, OUT_UNITS=KM-S, TIME_TYPE=TDB`. Output includes ICRF position km and velocity km/s.
   - **Apparent**: `EPHEM_TYPE=OBSERVER, CENTER='500@399', QUANTITIES='45', APPARENT=AIRLESS, REF_SYSTEM=ICRF, ANG_FORMAT=DEG, TIME_TYPE=TT`. Output includes inertial apparent RA and Dec degrees. **Do not compare raw numerical TT and TDB timestamps as identical physical instants**.
3. Archive **all 12 original Horizons responses**, exact source-labelled query URLs and parameters, request signature, provenance and SHA-256. Derive the 300 structured rows from these raw responses, never from Aria.
4. Validate exact target IDs, row counts, epochs, units, reference settings, table completeness, angular range, source-model labels, and **SHA-256 against immutable originals**. Fail closed on a missing/malformed/mismatched response; never fill a gap with an Aria or interpolated value.
5. Keep live acquisition **one-shot and explicit**. Offline tests and integrity verification must not make network calls. Publish source attribution and an acquisition/provenance report for WP5.2.

## Exclusions and numerical limitations

WP5.1 does **not** compare Aria's output to Horizons, establish source-model uncertainty, derive tropical longitudes from inertial RA/Dec, locate retrograde stations, certify event timing, certify full interval accuracy or produce a commercial-release gate. No change to `src/ariaephemeris/`, public calculation contracts, Aria Galaxy, deployment or any original SPK binaries.

Horizons' current source labels may differ from Aria's chosen JPL files. Differences cannot automatically be classified as implementation defects; WP5.2 must explicitly separate model/observer/correction effects before applying numerical tolerances. The stored 25 epochs per body are *sample fixtures*, never a continuous error-bound guarantee.
